CHANGE:
  Added the Teacher data model and a full admin management screen.
  Specifically:
  - New DB tables: wpes_teachers (name, email, status) and
    wpes_teacher_classes (many-to-many: which classes/subjects a
    teacher is suitable to teach). Bumped DB_VERSION 1.4.0 -> 1.5.0
    and WPES_VERSION to match (per AGENTS.md schema-change rule).
  - New columns on wpes_sessions: assigned_teacher_id (nullable FK)
    and teacher_assigned_at (audit timestamp).
  - New class WPES_Teachers: CRUD, class-assignment, and
    get_teachers_for_class() (the lookup future invite logic will
    use to find "suitable teachers" for a session).
  - New admin submenu "Teachers" (list, add/edit modal with a
    class/subject checklist, archive, delete) — mirrors the
    existing Classes screen's UI pattern exactly.
  - Sessions admin screen: added a "Teacher" column and an
    assigned-teacher dropdown in the Edit Session modal (dropdown
    is populated per-class via a new AJAX endpoint, since only
    teachers linked to that session's class are valid choices).
    This is a manual admin control only in this pass — no
    automatic invite/accept-link workflow yet (that is the next
    piece of work).
  - WPES_Sessions::query() (admin listing) now LEFT JOINs the
    teacher name; WPES_Sessions::update() now accepts
    assigned_teacher_id as an editable field.

REASON:
  Developer Specification section 10 ("Teacher Assignment via
  Email and Accept Link") and the client's direct instruction
  ("the complete Teacher workflow has not been implemented yet...
  implement the required Teacher functionality"). This is the
  foundation everything else in the spec (minimum-participant
  confirmation, automatic invites, payment capture trigger) will
  attach to, so it went first. No existing functionality was
  changed in behavior — only additive: new tables, new columns
  (nullable, default unassigned), new admin screen, new optional
  form field. Existing booking/checkout/payment flow untouched.

DEPLOY NOTE (for the live-site migration later):
  Ship all 9 files above together. On first admin page load after
  deploy, WPES_Admin::init() calls WPES_Activator::maybe_upgrade(),

  change (new tables + new nullable columns) — no manual DB step
  needed. Fully backwards compatible: existing sessions simply
  start with assigned_teacher_id = NULL ("Unassigned").
